# Регистрация своего логина и пароля

## Подготовка

1. Скачайте актуальный репозиторий. Если он уже клонирован, выполните `git pull` в папке Materials. Без Git можно заново скачать Code → Download ZIP.
2. В этой папке скопируйте settings_example.py в settings.py. Впишите свой пароль PostgreSQL, проверьте user, host и port.
3. В Query Tool базы postgres отдельно выполните 00_create_database.sql, включив Auto commit, если базы ещё нет.
4. Откройте новый Query Tool базы **mini_profiles**. Выполните 01_tables.sql, затем 02_seed.sql.
5. Откройте терминал в этой папке: `python3 app.py` (либо python app.py, если ваша команда называется python).

## Что показывает

Новый пользователь сам вводит логин и пароль. «Зарегистрироваться» сохраняет профиль в PostgreSQL. «Войти» читает его из БД, проверяет пароль и открывает простое второе окно. Никаких товаров, склада или формы основного задания здесь нет.

## Проверьте по порядку

1. Введите новый логин длиной 3–30 символов и учебный пароль длиной 6–128 символов.
2. Нажмите «Зарегистрироваться»; пароль очистится. Снова введите тот же пароль.
3. Нажмите «Войти»: появится второе окно с логином.
4. Вернитесь кнопкой или крестиком. Попробуйте неверный пароль: второе окно не откроется.
5. Повтор регистрации того же логина даст предупреждение.
6. Закройте программу и запустите снова: зарегистрированный профиль остаётся в БД.

## Ключевые строки

- `get()` читает Entry; `strip()` убирает крайние пробелы логина.
- `len()` считает символы; SQL `length()` проверяет такую же длину на стороне БД.
- `создать_хеш(пароль)` возвращает защищённое значение для хранения. `password_tools.py` лежит рядом, переписывать его не нужно.
- INSERT передаёт два значения через `%s` и `(логин, хеш)`. Пароль открытым текстом не сохраняем.
- Успешный выход из `with psycopg.connect(...)` фиксирует INSERT.
- `UniqueViolation` — повтор ключа login; остальные ошибки PostgreSQL обрабатываем отдельно.
- SELECT ищет по логину, `fetchone()` возвращает одну строку или None. `(логин,)` — кортеж одного параметра, запятая обязательна.
- `проверить_пароль(пароль, запись[0])` использует сохранённое значение для проверки; простой `==` вместо неё не подходит.
- `Toplevel` создаёт второе окно; `withdraw` скрывает первое, `deiconify` показывает обратно.

Для подключения user/password из settings.py относятся к PostgreSQL, а логин/пароль полей — к профилю этого примера. Это разные пары. Пользуйтесь только вымышленными учебными паролями.

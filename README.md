# Учебные материалы: самостоятельные мини-системы

Примеры Python + Tkinter + PostgreSQL. В каждой папке — отдельная небольшая программа, SQL для её базы и инструкция. Вы скачиваете проект, создаёте базы **на своём компьютере** и проверяете работу примеров.

## Что изучать

1. **[Клуб читателей](01_Клуб_читателей/README.md)** — вход по одному коду, переход в новое окно, загрузка списка книг и возврат назад.
2. **[Список дел](02_Список_дел/README.md)** — ввод одной записи, сохранение в PostgreSQL и обновление Treeview. Проверка пустого ввода и повторов.
3. **[Расписание кружков](03_Расписание_кружков/README.md)** — поиск по тексту: вводишь день недели, получаешь подходящие кружки.
4. **[Рейтинг команд](04_Рейтинг_команд/README.md)** — отбор по минимальному баллу и сортировка по возрастанию или убыванию.
5. **[Карточка курса](05_Карточка_курса/README.md)** — поиск одной записи через `fetchone()`, вывод ответа в надпись Label.
6. **[Журнал посещений](06_Журнал_посещений/README.md)** — сохранение имени с автоматической сегодняшней датой, проверка повтора за день.
7. **[Абонементы](07_Абонементы/README.md)** — работа с ценой через Decimal, отбор «не дороже» и сортировка стоимости.
8. **[Календарь](08_Календарь/README.md)** — ввод даты, проверка её правильности и поиск событий этого дня.
9. **[Регистрация и вход](09_Регистрация_и_вход/README.md)** — создать собственные логин и пароль, сохранить профиль, проверить вход и открыть второе окно.
10. **[Диапазон «От–До»](10_Диапазон_две_границы/README.md)** — два Entry, BETWEEN с двумя параметрами, включённые границы и оба направления сортировки.
11. **[Анкета с разными типами](11_Анкета_разные_типы/README.md)** — несколько Entry, проверка текста, суммы, целого и даты, INSERT и повторный SELECT в Treeview.

**[SQL-памятка](SQL_памятка/README.md)** — length(), btrim(), CHECK, NOT NULL, ключи и параметры SQL с отдельными короткими запросами.



В примерах 01–08 используется одно поле ввода. Пример 09 показывает регистрацию и вход с логином и паролем, 10 — диапазон с двумя границами, 11 — несколько полей разных типов. Учебный код старого примера клуба: **Club2026!**. В новом примере регистрации вы создаёте свою учётную запись.

## Дополнение к материалам

Добавлены примеры **09, 10, 11** и **SQL-памятка**. Если проект уже клонирован, выполните `git pull` в папке Materials. Если скачивали ZIP — скачайте актуальный ZIP заново. В новых папках отдельно создайте settings.py и соответствующие базы по README. Старые папки не удалялись.

## 1. Скачайте материалы

В терминале выполните:

```bash
git clone https://github.com/PKO-LP/Materials.git
```

Перейдите в скачанную папку:

```bash
cd Materials
```

Либо скачайте репозиторий через **Code → Download ZIP**, распакуйте его и откройте папку проекта в редакторе. Создавать все базы сразу не обязательно: можно начать с одного примера.

## 2. Проверьте программы и библиотеку

На вашем компьютере должны быть установлены Python, PostgreSQL и pgAdmin. Сервер PostgreSQL должен быть запущен. Логин, пароль, адрес и порт подключения используйте **свои**.

Команды выполняйте по одной в терминале:

```bash
python3 --version
```

Проверка Tkinter — откроется небольшое окно. После проверки закройте его:

```bash
python3 -m tkinter
```

Проверка Psycopg — должен появиться номер версии:

```bash
python3 -c "import psycopg; print(psycopg.__version__)"
```

Только если Psycopg отсутствует, установите его из корня Materials:

```bash
python3 -m pip install -r requirements.txt
```

После установки повторите проверку импорта. При каждом запуске примеров переустанавливать библиотеку не нужно. Если Python или Tkinter не запускаются, сначала исправьте их установку.

На Windows команда может называться `python` вместо `python3`. Используйте одно имя при проверке, установке и запуске. В редакторе выберите тот же Python.

## 3. Настройте один выбранный пример

1. Откройте папку нужной мини-системы и её README.
2. Внутри этой папки скопируйте **settings_example.py** и назовите копию **settings.py**. Оба файла могут остаться рядом, удалять образец не нужно.
3. В settings.py замените `ВАШ_ПАРОЛЬ` своим паролем PostgreSQL. Проверьте user, host и port. dbname оставьте таким, как в SQL выбранного примера.
4. Сохраните settings.py рядом с app.py. Строка `from settings import DB` читает именно этот файл.

Файла с действующим паролем в репозитории нет. Ваш settings.py исключён из публикации через .gitignore.

## 4. Создайте базу и заполните таблицы

1. В pgAdmin подключитесь к своему серверу и откройте Query Tool базы **postgres**.
2. Включите **Auto commit**. Отдельно выполните **00_create_database.sql** из выбранной папки. Если такая база уже есть, повторять её создание не нужно.
3. Обновите список Databases. Выберите созданную базу и откройте **новый Query Tool именно для неё**.
4. Выполните **01_tables.sql** — создание таблиц.
5. Выполните **02_seed.sql** — начальные демонстрационные записи.
6. Выполните запросы **03_check.sql** по одному и посмотрите результаты.

Имена баз у примеров разные. Не выполняйте создание таблиц выбранного примера в базе другого примера.

## 5. Запустите программу

Откройте терминал **в папке выбранного примера**, где находятся app.py и ваш settings.py:

```bash
python3 app.py
```

На macOS после настройки можно использовать ЗАПУСТИТЬ.command из этой папки. Он не создаёт базу и не заполняет settings.py — эти действия нужно выполнить заранее.

Если подготовили несколько примеров, из корня Materials можно открыть меню:

```bash
python3 Открыть_пример.py
```

Проверки кнопок и ожидаемые результаты приведены в README каждой папки и в [самопроверке](Самопроверка.md).

## Подготовить все базы одним запуском

Этот вариант необязателен. Сначала создайте и заполните **settings.py в каждой папке примера**. Пользователь PostgreSQL должен иметь право создавать базы. Затем из корня Materials выполните:

```bash
python3 Подготовить_все_БД.py
```

Скрипт создаёт отсутствующие базы и таблицы, добавляет недостающие начальные строки. Существующие данные он не удаляет. Если структура ранее созданной таблицы отличается от SQL примера, скрипт её не переделывает — сначала проверьте, к какой базе вы подключаетесь.

## Как изучать примеры

Запустите один пример → объясните действие кнопки → измените одно значение → проверьте результат. Не соединяйте разные app.py копированием подряд: это отдельные программы, каждая со своим окном и своей базой. Возьмите нужный приём и примените его в своей работе.

## Пошаговая сборка системы тестирования

В папке `tk_system` находится простая сборка по обновлённому финальному ТЗ: две роли, один готовый тест из пяти вопросов, оценка ученику и результаты преподавателю. Один основной файл app.py, три таблицы, без JOIN и редактора вопросов. Начните с README.md этой папки, затем выполняйте документы 01–05 по порядку. Предыдущая усложнённая сборка заменена версией для начинающих.

# Простая система тестирования — собираем по порядку

Ученик проходит пять вопросов и видит свои оценки. Преподаватель видит все результаты. При регистрации выбирают роль, преподавателя ученику выбирать не нужно.

## Сначала новая папка

Создайте **новую пустую папку testing_app** и откройте именно её в редакторе. Не дописывайте эту систему в старый пример.

Из материалов скопируйте только вспомогательные файлы:

- password_tools.py — готовые функции защиты пароля;
- settings_example.py — скопируйте под именем settings.py и задайте свой пароль PostgreSQL;
- requirements.txt — готовый список библиотек.

Создайте пустой app.py рядом. Остальные файлы создавайте **сами в этой же папке**, строго под именами из шагов. Готовых app.py и SQL-файлов для скачивания здесь нет. Внутри инструкций показано, как собрать их по строкам.

## Строгая последовательность

1. **01_Подготовка.md, блок А:** папка, помощники и проверка установленных программ.
2. **Тот же документ, Б1–Б4:** сами соберите четыре SQL-файла и сохраните их. Пока ничего не выполняйте в pgAdmin.
3. **Б5:** проверьте, что все четыре файла появились в своей папке и не пустые.
4. **В1–В5:** берите именно свои файлы из Б1–Б4, открывайте их в Query Tool и выполняйте в указанной базе.
5. **Г:** проверьте, что база и три таблицы созданы, а вопросы заполнены. Если нет — вернитесь к указанному предыдущему шагу.
6. **02_Вход_и_регистрация.md:** только теперь начинайте заполнять свой app.py.
7. **03_Тест_и_оценка.md:** продолжайте тот же app.py.
8. **04_Результаты_и_запуск.md:** завершите app.py и запустите его.
9. **05_Проверка_и_словарь.md:** зарегистрируйтесь, пройдите тест и снова выполните проверки из того же 03_check.sql, который собрали в Б4.

06_Готовые_помощники.md — необязательный разбор двух готовых вспомогательных файлов. Для основного пути достаточно скопировать их по блоку А; повторно дописывать в них код не нужно.

## Итоговая структура вашей папки

```text
testing_app/
    app.py
    password_tools.py
    requirements.txt
    settings.py
    00_create_database.sql
    01_schema.sql
    02_questions.sql
    03_check.sql
```

SQL-файлы сохраняете вы в Б1–Б4. app.py собираете вы в документах 02–04. Эти файлы не появляются автоматически после скачивания материалов.

**Запускается app.py.** Он импортирует settings.py и password_tools.py. SQL-файлы открываются и выполняются в pgAdmin, а requirements.txt используется только при необходимости установки библиотеки. Сохранить SQL-файл и выполнить его — два разных шага.

## Как читать зелёные и красные строки

Пример ниже только объясняет обозначения. В приложение эти print добавлять не нужно.

```diff
 print("1")
-print("2")
+print("3")
```

- Обычная строка print("1") уже есть — оставьте её, повторно не пишите.
- Красную строку со знаком − удалите из своего файла.
- Зелёную строку со знаком + добавьте. Сам знак + не пишите, отступы после него сохраните.

В результате остаются print("1") и print("3"). В нашей сборке почти всё добавляется: красные строки будут нужны только при замене уже написанного кода.

Перед каждым действием указано имя файла. В рамке показаны две предыдущие строки и одна новая зелёная. Так видно точное место: допишите её после обычных строк. Если обычные строки не совпадают с вашим файлом, вернитесь к предыдущему действию этого документа.

В документах 02–04 продолжается один app.py, с начала до конца. В документе 01 аналогично собираются SQL-файлы; в 06 — необязательный разбор настроек и готового помощника. SQL выполняйте только целой законченной командой, а не по одной строке таблицы.

Окно появится после завершения документа 04. До этого можно проверять синтаксис законченных функций через python3 -m py_compile app.py. Отсутствие ошибки не означает, что уже собрана вся программа.

Когда всё соберёте: создайте через интерфейс преподавателя и ученика, войдите учеником, пройдите тест, посмотрите оценку. Затем войдите преподавателем и откройте все результаты.

## Как части работают вместе

Файл с запросом → выполнение в pgAdmin → настоящая база с таблицами и вопросами → подключение через settings.py → регистрация из app.py добавляет пользователя → завершение теста добавляет результат → сохранённый 03_check.sql позволяет увидеть эти новые строки в pgAdmin.

Пока предыдущий результат не получен, к следующему блоку не переходите. Каждый блок выполнения называет файл и более ранний блок, где вы его собрали.

Учебный пример: склад магазина. Регистрация → вход → отдельное окно → чтение таблицы → добавление → поиск по названию и диапазон цен → сортировка → выход. Используются функции, без собственных классов.

Это подробная учебная сборка рабочего примера. Сверяйте названия таблиц, поля и требования со своим техническим заданием. Подсказка не заменяет проверку требований.

Все файлы создавайте в одной папке. Команды терминала выполняйте из этой папки. SQL вводите в Query Tool pgAdmin. Python пишите в редакторе, в файле app.py.

## 1. Подготовка

Сначала проверьте установленное. Команды выполняются отдельно:

```sh
python3 --version
```

```sh
python3 -m tkinter
```

```sh
python3 -c "import psycopg; print(psycopg.__version__)"
```

Первая команда показывает версию Python; вторая открывает тестовое окно — закройте его; третья проверяет библиотеку подключения. Если только psycopg отсутствует, установите её:

```sh
python3 -m pip install "psycopg[binary]>=3.2,<4"
```

Если отсутствует Python или Tkinter, исправьте установку до начала сборки. Повторная установка psycopg не исправляет отсутствие Tkinter.

Скопируйте settings_example.py в новый файл settings.py в этой же папке. Образец можно оставить. В settings.py замените ВАШ_ПАРОЛЬ своим паролем PostgreSQL. Программа импортирует именно settings.py. DB — словарь параметров: dbname — база, user — пользователь сервера, password — его пароль, host — адрес, port — порт, connect_timeout — ожидание подключения в секундах. Пароль сервера отличается от будущих паролей пользователей приложения.

password_tools.py оставьте рядом: это готовая вспомогательная часть для защиты пароля. создать_хеш получает пароль и возвращает строку для сохранения; проверить_пароль получает введённый пароль и сохранённую строку, возвращает True или False.

## 2. Создаём базу

В pgAdmin подключитесь к серверу, откройте Query Tool базы postgres. Выполните один раз:

```sql
CREATE DATABASE tk_shop_practice;
```

CREATE — создать; DATABASE — базу данных; tk_shop_practice — выбранное имя; точка с запятой завершает команду. Если база уже существует, повторно её создавать не нужно. Обновите список баз и откройте Query Tool именно tk_shop_practice.

Проверьте выбранную базу:

```sql
SELECT current_database();
```

SELECT получает значение; current_database() возвращает имя текущей базы. Ответ должен быть tk_shop_practice.

## 3. Таблицы и начальные строки

Выполните определения отдельно. Строки внутри одного CREATE TABLE являются одной командой: завершите её до выполнения.

```sql
CREATE TABLE IF NOT EXISTS public.shop_users (
    login TEXT PRIMARY KEY CHECK (length(login) BETWEEN 3 AND 30),
    password_hash TEXT NOT NULL
);
```

```sql
CREATE TABLE IF NOT EXISTS public.shop_products (
    title TEXT NOT NULL CHECK (btrim(title) <> ''),
    category TEXT NOT NULL CHECK (btrim(category) <> ''),
    price NUMERIC(10, 2) NOT NULL CHECK (price > 0),
    quantity INTEGER NOT NULL CHECK (quantity >= 0),
    received_on DATE NOT NULL,
    PRIMARY KEY (title, category)
);
```

CREATE TABLE создаёт таблицу; IF NOT EXISTS означает «если ещё нет». public — схема, точка отделяет её от имени таблицы. shop_users и shop_products — имена, подчёркивание просто соединяет слова. Скобки содержат описание полей; запятые разделяют поля и ограничения.

TEXT — текст; INTEGER — целое число; DATE — дата; NUMERIC(10, 2) — точное число, всего до десяти цифр, из них две после точки. NOT NULL запрещает отсутствие значения. PRIMARY KEY запрещает повторы и NULL: у пользователя ключ — login; у товара — сочетание title и category. CHECK проверяет условие. length считает символы, BETWEEN 3 AND 30 включает обе границы, btrim убирает крайние пробелы, <> означает «не равно», > и >= — «больше» и «не меньше». Пустые кавычки '' — пустой текст.

Откройте 02_products.sql и выполните INSERT как одну команду. Это десять демонстрационных товаров. INSERT INTO указывает таблицу, скобки после имени — порядок столбцов, VALUES — значения в том же порядке. Один набор скобок — один товар. ON CONFLICT не добавляет повторную запись с тем же ключом. Пользователей заранее не добавляем: их создаёт регистрация.

## Словарь для сборки

- `=` присваивает значение; `==` сравнивает; `!=` означает «не равно»; `not` — отрицание, `or` — хотя бы одно условие, `and` — оба. `None` означает отсутствие значения; `True` и `False` — да и нет.
- `len` считает элементы или символы. `int` превращает строку в целое число. `str` получает текст. Неверное преобразование вызывает ошибку.
- `Decimal` получает точную сумму из текста. `replace(",", ".")` заменяет запятую точкой; `is_finite` исключает бесконечность и NaN; `quantize(Decimal("0.01"))` приводит к сотым. `raise ValueError` направляет неверный ввод в обработчик ошибки.
- `date.today()` — сегодняшняя дата; `date.fromisoformat` разбирает текст даты; `isoformat` возвращает ГГГГ-ММ-ДД. Несуществующая дата вызывает ValueError.
- `tk.Tk()` — главное окно, `tk.Toplevel(окно)` — дочернее. `title` — заголовок, `geometry` — ширина и высота в пикселях, `minsize` — минимальный размер. `withdraw` скрывает окно, `deiconify` возвращает, `destroy` уничтожает. `protocol("WM_DELETE_WINDOW", функция)` назначает действие крестику.
- `config` и `configure` меняют настройки уже созданного виджета. `command=функция` передаёт действие, а `command=функция()` немедленно вызовет его и обычно испортит привязку.
- `focus_set` переводит курсор в поле. `Entry.insert(0, текст)` помещает текст в начало поля.
- `Treeview` получает родителя, `columns` — последовательность имён столбцов, `show="headings"` скрывает служебную колонку дерева, `height=5` показывает пять строк. Измените на 3: видимая часть станет ниже. `get_children` возвращает идентификаторы строк; `delete` удаляет строку виджета; `insert("", tk.END, values=...)` добавляет строку в конец на верхнем уровне дерева.
- `width` у столбцов Treeview задаётся в пикселях; `anchor="center"` выравнивает по центру, `"w"` — по левому краю. `columnconfigure(1, weight=1)` разрешает второму столбцу формы получать свободную ширину.
- `Scrollbar` — полоса прокрутки; `orient="vertical"` — вертикальная; `command=таблица.yview` перемещает таблицу. Обратная связь `yscrollcommand=прокрутка.set` перемещает ползунок при прокрутке таблицы. Нужны обе связи.
- `fill="x"` растягивает по горизонтали, `fill="y"` — по вертикали, `side="left"` и `"right"` — размещение слева/справа. `sticky="ew"` растягивает по горизонтали в ячейке grid. Не применяйте pack и grid к детям одного родителя: здесь у каждого Frame свой способ размещения.
- `SELECT` выбирает столбцы; `FROM` задаёт таблицу; `WHERE` оставляет подходящие строки. `ORDER BY price ASC` — дешевле сначала, `DESC` — дороже сначала. `title, category` после цены задают порядок при одинаковой цене.
- `BETWEEN %s AND %s` включает обе границы цены. `ILIKE %s` ищет текст без учёта регистра; `%` в переданном значении означает любые символы. Пустое поле даёт `%%`, то есть все названия. Знаки `%` и `_`, введённые в поиск, тоже действуют как шаблоны PostgreSQL.
- `%s` — место для значения в psycopg. Значения передаются вторым аргументом execute. Для одного значения нужен кортеж `(логин,)` с запятой. Не подставляйте ввод пользователя через f-строку в SQL.
- `sql += ...` дописывает текст к запросу. В этой сборке варианты ASC/DESC заданы самим кодом, а пользовательские значения передаются только параметрами.
- `запись[0]` берёт первый столбец ответа. `название, категория, цена, количество, дата = товар` распределяет пять столбцов по пяти переменным.
- `f"{цена:.2f}"` показывает две цифры после точки; `f"...{len(товары)}"` вставляет число строк в текст.
- `mainloop()` запускает обработку событий: нажатий, ввода, закрытия окон. Он один, в самом конце программы. Удаление этой строки приведёт к завершению программы без рабочего интерфейса.

## Проверяем соединение частей

Теперь сохраните файл и запустите:

```sh
python3 app.py
```

1. Создайте новый логин из 3–30 символов и пароль из 6–128 символов. Нажмите регистрацию. Повтор того же логина должен показать предупреждение.
2. Введите неверный пароль: окно склада не должно открыться. Введите правильный: откроется склад, окно входа скроется.
3. В таблице должны быть десять начальных товаров, но видны пять строк. Проверьте колесо мыши и полосу прокрутки.
4. Добавьте свой товар: заполните название, категорию, положительную цену, целое неотрицательное количество, существующую дату. После добавления программа сохраняет запись и заново читает БД.
5. Попробуйте пустое название, цену «abc», количество -1, дату 2026-02-30, повтор названия и категории: появятся сообщения, неверная запись не сохранится.
6. Введите часть названия и нажмите одну из кнопок сортировки: они одновременно применяют поиск и границы цены. Затем проверьте обе границы, только нижнюю и только верхнюю. Поменяйте местами нижнюю и верхнюю: должно появиться предупреждение.
7. Нажмите «Все товары»: поиск и цены очистятся. «Очистить таблицу» очищает только экран; «Все товары» вернёт записи из БД.
8. Закройте склад крестиком: вернётся вход. Полностью закройте и заново запустите программу: зарегистрированный пользователь и новый товар должны сохраниться.

Проверки в pgAdmin выполняйте по одной в базе tk_shop_practice:

```sql
SELECT COUNT(*) FROM public.shop_products;
```

COUNT(*) считает все строки. После одного успешного добавления к исходным десяти будет одиннадцать.

```sql
SELECT login FROM public.shop_users ORDER BY login;
```

Показывает логины по алфавиту. Содержимое password_hash выводить не нужно.

```sql
SELECT title, category, price, quantity, received_on FROM public.shop_products WHERE price BETWEEN 500 AND 1000 ORDER BY price ASC, title, category;
```

Это отдельная проверка диапазона в SQL: числа здесь написаны непосредственно, поскольку запрос выполняется вручную в pgAdmin. В Python вместо введённых пользователем значений остаются параметры %s.

Если программа не стартует: проверьте имя settings.py, наличие password_tools.py рядом и выбранную базу. Если ошибка отступов: сравните пробелы в добавленной строке и соседних строках той же функции. Если таблица не найдена: проверьте current_database и выполнение CREATE TABLE именно в нужной базе.

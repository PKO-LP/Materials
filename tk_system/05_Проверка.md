# 5. Проверяем готовую сборку

1. Откройте регистрацию. В ней только роль, ФИО, логин, пароль и повтор пароля. Поля «Ваш преподаватель» нет.
2. Зарегистрируйте ученика и преподавателя. Неполные поля, короткий пароль, несовпавший повтор, повтор логина другим регистром должны вызвать предупреждение.
3. Войдите неверным паролем, затем верным паролем с неверной ролью: кабинет не должен открыться. Правильные данные открывают кабинет соответствующей роли.
4. Преподаватель видит пять общих вопросов. Смените номер, отредактируйте текст/варианты и правильный ответ. Сохраните. Пустые значения не принимаются. После повторного входа изменения остаются.
5. Ученик нажимает «Начать тест»: получает пять вопросов. Между вопросами можно переходить, выбранные ответы сохраняются. Правильные ответы и оценка пока не показываются.
6. Попробуйте завершить с пропуском: должно появиться предупреждение. После пяти выбранных ответов сохранится попытка и появится оценка. Даже ноль совпадений сохраняется с оценкой 2.
7. Повторное нажатие завершения не создаёт дубликат. Новое прохождение создаёт новую попытку.
8. Преподаватель открывает «Мои ученики»: здесь все ученики системы. У непройденного теста дата «Не проходил», остальные результаты — прочерки. «Обновить» заново читает БД.
9. Выберите завершённую попытку и нажмите «Подробнее». В отдельном окне должны быть все вопросы, варианты, выбранный и правильный ответы, результат по каждому.
10. Начните попытку учеником. Во втором экземпляре приложения измените вопрос преподавателем. Первая попытка должна завершаться по своей старой копии. Новая получает изменённый тест. Старый подробный разбор и оценки не меняются.
11. Закройте программу и запустите снова: пользователи, тест и завершённые попытки должны остаться.
12. Убедитесь, что выбор роли «Преподаватель» не даёт ученику войти в редактор. Проверка роли должна происходить и внутри функций данных, как в service.py.

## Откуда берётся оценка

Выборы ученика → сравнение с правильными номерами из снимка → счётчик совпадений → оценка → INSERT попытки и пяти ответов → вывод результата.

Пять совпадений дают 5, четыре — 4, три — 3, от нуля до двух — 2. Увеличение счётчика происходит только в Python. Запись выполняется внутри finish_attempt после проверки всех пяти ответов.

## Что проверить в PostgreSQL

Выполняйте отдельно в базе final_up_shared:

```sql
SELECT COUNT(*) FROM questions;
```

Должно быть 5.

```sql
SELECT student_id, correct_count, grade FROM attempts ORDER BY finished_at DESC;
```

Здесь завершённые попытки. Повторные прохождения не заменяют предыдущие.

```sql
SELECT position, chosen_option, correct_option FROM answers WHERE attempt_id = %s ORDER BY position;
```

Последний запрос — шаблон для Python: вместо %s передайте UUID выбранной попытки отдельным аргументом execute. В pgAdmin укажите конкретный UUID в одинарных кавычках вместо %s. Должны вернуться пять ответов.

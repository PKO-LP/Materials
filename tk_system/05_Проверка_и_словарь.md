# 5. Проверка и словарь

## Сначала проверьте регистрацию и вход

1. Запустите python3 app.py из папки программы.
2. Нажмите «Создать аккаунт». Придумайте логин ученика и пароль от восьми символов. Роль оставьте «Ученик». Зарегистрируйтесь.
3. Попробуйте тот же логин ещё раз, в том числе большими буквами. Должно появиться сообщение, что он занят.
4. Попробуйте короткие логин/пароль: сохранения быть не должно.
5. Войдите неверным паролем: кабинет не открывается. Войдите верным: видны «Пройти тест», «Мои оценки», «Выйти».
6. Выйдите и создайте ещё один аккаунт с ролью «Преподаватель». После входа он увидит «Все результаты», а кнопки прохождения у него не будет.

Не путайте эти пароли с паролем PostgreSQL в settings.py. Аккаунты приложения вы создаёте сами через форму.

## Проверяем тест и сохранение

1. Войдите учеником и откройте тест. Должны появиться пять вопросов, по четыре варианта у каждого.
2. Нажмите завершение с пропуском. Появляется предупреждение, в results новой строки ещё нет.
3. Выберите все ответы. После завершения появляется оценка и кнопка завершения выключается.
4. Проверьте разные результаты: 5 верных — 5; 4 — 4; 3 — 3; 0, 1 или 2 — 2.
5. Вернитесь в кабинет и откройте «Мои оценки». Видны только строки с вашим логином.
6. Пройдите тест ещё раз. Вторая строка добавляется, первая остаётся.
7. Войдите другим учеником: его список не показывает чужие результаты.
8. Войдите преподавателем: видны результаты всех учеников. «Обновить» заново читает базу.
9. Полностью закройте программу и откройте: аккаунты и оценки остались.

Программа не сохраняет незавершённый тест. Кнопка «В кабинет» во время теста отменяет текущие несохранённые выборы; новое прохождение начинается с нуля.

## Возвращаемся к файлу проверки, который уже собрали

Не создавайте новые запросы и не скачивайте готовый скрипт. Используйте **testing_app/03_check.sql**, который вы сами собрали в **01_Подготовка.md, блок Б4** и впервые выполнили в **В5**.

1. После регистрации откройте pgAdmin → final_up_beginner → Query Tool.
2. Нажмите Open File и выберите свой testing_app/03_check.sql.
3. Выделите первый SELECT current_database(); и выполните Execute script: в Data Output должно быть final_up_beginner.
4. Выделите сохранённый SELECT login, role ... FROM users и выполните: теперь должны появиться зарегистрированные через приложение пользователи. До регистрации таблица была пустой — сравните с результатом блока Г.
5. Выделите SELECT id, question, correct ... FROM questions: по-прежнему пять вопросов, добавленных файлом из Б3.
6. После завершения теста вернитесь к этой же вкладке, выделите последний SELECT student_login, score, grade ... FROM results и выполните его. Появятся логин, количество верных и оценка.
7. Пройдите тест ещё раз и повторите последний SELECT: появится новая строка, предыдущая останется.

Старый вывод в pgAdmin автоматически не обновляется. Каждый раз выполняйте нужный SELECT заново. Если результата нет, проверьте, что тест действительно завершён без пропусков, приложение сообщило результат и выбрана та же база, что указана в settings.py. Если сам файл проверки отсутствует — вернитесь в Б4, а не пропускайте проверку.

## Главное: что означают индексы

Одна строка пользователя содержит три значения, потому что во входе SELECT выбирает login, password_hash, role:

- пользователь[0] — логин;
- пользователь[1] — хеш;
- пользователь[2] — роль.

Одна строка вопроса содержит семь значений в порядке SELECT:

- вопрос[0] — id;
- вопрос[1] — текст вопроса;
- вопрос[2], вопрос[3], вопрос[4], вопрос[5] — четыре варианта;
- вопрос[6] — номер правильного варианта от 1 до 4.

В Python номера элементов начинаются с нуля. Варианты ответа для ученика нумеруются с единицы. Поэтому при номер=1 выражение вопрос[номер + 1] берёт вопрос[2], то есть текст первого варианта.

выборы[номер].get() получает выбранный вариант одного вопроса. вопросы[номер][6] получает правильный вариант этого же вопроса. Их сравнение даёт одно совпадение или несовпадение. После цикла INSERT сохраняет только итог: логин, количество и оценку.

## Короткий словарь

- def объявляет функцию, command=имя_функции связывает её с кнопкой. Скобки после имени в command не ставим: иначе функция вызовется сразу.
- global разрешает менять общую переменную внутри функции. Например, пользователь запоминается после входа и очищается при выходе.
- None означает отсутствие значения, True — да, False — нет. Список [] хранит несколько элементов, append добавляет следующий.
- if / elif / else выбирают действие по условию; == сравнивает, != означает «не равно», not — отрицание, or — хотя бы одно условие. return выходит из функции.
- for повторяет вложенные строки. range(5) даёт 0, 1, 2, 3, 4; range(1,5) — 1, 2, 3, 4. Отступы показывают, какие строки повторять.
- get читает ввод, strip убирает крайние пробелы, lower приводит логин к нижнему регистру. Пароль не обрезаем и не меняем.
- запрос — наша функция. sql — текст команды; параметры — отдельные значения; читать=True просит вернуть строки SELECT. Пустой список означает «ничего не найдено», None — ошибку запроса.
- %s — место значения в psycopg. Вторым аргументом передайте кортеж, например (логин,). Запятая нужна даже для одного значения. Не склеивайте ввод пользователя с SQL.
- with закрывает соединение после работы; при успехе сохраняет INSERT. cursor выполняет execute, fetchall читает все строки. try / except перехватывают ошибку БД и показывают сообщение.
- SELECT читает; FROM задаёт таблицу; WHERE оставляет нужные строки; ORDER BY сортирует; DESC — новые номера сверху. INSERT INTO ... VALUES добавляет строку. Пояснения создания таблиц — в документе 01.
- Tk создаёт главное окно. Frame объединяет виджеты, Label показывает текст, Entry принимает ввод, Button запускает функцию, Combobox даёт выбор роли, Radiobutton — один ответ, Treeview — таблицу.
- geometry задаёт размер в пикселях. title — заголовок окна, text — текст, font — шрифт и размер, width у Entry — ширина в символах. show='*' скрывает пароль.
- pack показывает виджет; pady — отступ сверху/снизу, padx — слева/справа, side='left' ставит рядом, fill/expand позволяют занять свободное место. padding — внутренний отступ Frame. wraplength переносит длинную надпись.
- winfo_children перечисляет виджеты внутри области. destroy удаляет виджет с экрана. Так очищаем форму без удаления данных в БД.
- IntVar(value=0) хранит ответ. variable связывает переключатели одного вопроса, value — номер выбранного варианта. У каждого вопроса своя IntVar.
- state='readonly' запрещает ввод произвольной роли; state='disabled' выключает кнопку. config меняет свойство уже созданного виджета.
- columns — имена колонок Treeview, heading — заголовок, column — ширина в пикселях, height — видимые строки, show='headings' скрывает служебную колонку дерева. insert('', tk.END, values=строка) добавляет значения в конец таблицы. Колесом мыши можно прокручивать длинный список результатов.
- f'...{значение}...' вставляет значение в надпись. += 1 увеличивает счётчик на один, не обращаясь к БД.
- messagebox.showinfo/showwarning/showerror показывают сообщение/предупреждение/ошибку. Первый аргумент — заголовок, второй — текст, parent — родительское окно.
- mainloop запускает работу кнопок и ввода. Он один, в самом конце app.py.

Если возникает ошибка импорта, проверьте имена файлов и что они лежат рядом. Если ошибка подключения — PostgreSQL должен быть запущен, база создана, настройки в settings.py верные. При ошибке отступов сравните пробелы слева с показанными строками; не вставляйте фрагмент в случайное место.

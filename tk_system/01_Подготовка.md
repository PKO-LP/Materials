# 1. Подготовка

## Обязательно: начните с новой папки

**Всю работу выполняйте строго в новой отдельной папке `testing_app`.** Не собирайте программу внутри папок других примеров и не дописывайте её в старый проект.

1. Создайте новую пустую папку `testing_app` и откройте именно её в редакторе.
2. Создайте внутри пустой файл `app.py`. В него по шагам добавляется код приложения из документов 02–04.
3. Скопируйте из материалов `tk_system` готовый файл `password_tools.py` в эту же папку. Это вспомогательный модуль для защиты и проверки паролей; переписывать его не нужно.
4. Скопируйте туда же `settings_example.py` и переименуйте **копию** в `settings.py`. В `settings.py` замените `ВАШ_ПАРОЛЬ` своим паролем PostgreSQL. Исходный образец в материалах не меняйте.
5. Скопируйте туда же готовый `requirements.txt`. Это список библиотек, а не Python-программа.

Перед сборкой в новой папке должно получиться:

```text
testing_app/
    app.py
    password_tools.py
    requirements.txt
    settings.py
```

**Запускайте `app.py`.** В этой сборке `settings.py` и `password_tools.py` используются как вспомогательные модули: `app.py` сам подключает их через `from settings import DB` и `from password_tools import создать_хеш, проверить_пароль`. Отдельно запускать их для работы приложения не нужно — они сами не открывают окно. `requirements.txt` тоже не запускают.

Все четыре файла должны находиться рядом, как в примере. Не переносите помощники во вложенную папку и не переименовывайте их иначе: иначе показанные импорты не найдут файлы.

Терминал открывайте в этой же папке. Команда запуска после завершения сборки:

```sh
python3 app.py
```

Если проверка из документа 01 показала, что psycopg не установлен, используйте скопированный список зависимостей:

```sh
python3 -m pip install -r requirements.txt
```

Повторно устанавливать библиотеку при каждом запуске не требуется. SQL-файлы создавайте в этой же папке по документу 01, а выполняйте запросы в pgAdmin.


## Где что писать

Команды python3 выполняйте в терминале. SQL — в Query Tool pgAdmin. Код приложения — в редакторе, в app.py. Сначала создайте папку testing_app и откройте её в редакторе.

## Проверяем установленное

Каждую команду выполняйте отдельно:

```sh
python3 --version
```

Показывает версию Python. Если Python отсутствует, сначала установите его.

```sh
python3 -m tkinter
```

Должно появиться маленькое тестовое окно. Закройте его. Если tkinter отсутствует, нужен Python с Tcl/Tk.

```sh
python3 -c "import psycopg; print(psycopg.__version__)"
```

Если появилась версия, библиотека уже есть. Только если написано, что psycopg отсутствует, выполните:

```sh
python3 -m pip install "psycopg[binary]>=3.2,<4"
```

Для обычного запуска приложения повторно ничего устанавливать не нужно.

## Два готовых файла

1. Скопируйте password_tools.py в testing_app. Это готовый помощник: создать_хеш защищает пароль, проверить_пароль сравнивает введённый пароль с сохранённым хешем. Его не нужно переписывать.
2. Создайте settings.py в testing_app по документу 06_Готовые_помощники.md. Можно вместо этого скопировать settings_example.py и назвать копию settings.py. Образец можно оставить. В settings.py вместо ВАШ_ПАРОЛЬ укажите свой пароль PostgreSQL. Программа обращается именно к settings.py.

DB — словарь настроек: dbname — база, user — пользователь сервера, password — пароль сервера, host — адрес, port — порт, connect_timeout — сколько секунд ждать соединение. Пароль PostgreSQL и пароль аккаунта приложения — разные вещи.

## Как превратить SQL-файлы в работающую базу в pgAdmin

**Сохранить .sql-файл — не значит создать базу или таблицу.** Файл содержит текст команд. Чтобы PostgreSQL создал нужные объекты, откройте команды в pgAdmin и выполните их. Python затем подключается к созданной базе через settings.py; сами .sql-файлы приложение не запускает.

Ниже маршрут для четырёх файлов. Сначала соберите нужный файл по зелёным строкам из этого документа, затем выполните его указанным способом.

### 1. Подключитесь к своему серверу

1. Откройте pgAdmin.
2. Слева раскройте Servers, затем свой сервер PostgreSQL. Номер версии у вас может отличаться.
3. Если появится запрос пароля, введите пароль своего пользователя PostgreSQL. Это пароль сервера, а не пароль ученика в будущей программе.
4. Раскройте Databases. Там должна быть служебная база postgres.

### 2. Выполните 00_create_database.sql в базе postgres

1. Нажмите правой кнопкой на базе **postgres**.
2. Выберите **Query Tool** — откроется редактор SQL, подключённый именно к этой базе.
3. Внутри Query Tool нажмите **Open File** — кнопку открытия файла. Выберите собранный вами 00_create_database.sql из папки testing_app. Или скопируйте текст этого файла в редактор SQL.
4. В редакторе должна быть одна законченная команда CREATE DATABASE final_up_beginner; — без знака + из учебного примера.
5. Нажмите **Execute script** на панели Query Tool. Подведите курсор к кнопке, чтобы увидеть её название. Это действие отправляет команду серверу; обычное сохранение файла этого не делает.
6. Внизу откройте вкладку **Messages**: после успешного выполнения не должно быть ERROR, появится сообщение о выполнении команды.
7. Нажмите правой кнопкой на **Databases → Refresh**. В списке должна появиться **final_up_beginner**.

Если написано, что база уже существует, повторно её создавать не надо: найдите её в списке и переходите дальше. Если появилось другое ERROR, сначала прочитайте его и исправьте причину; не считайте шаг выполненным.

### 3. Откройте НОВЫЙ Query Tool для final_up_beginner

1. Нажмите правой кнопкой на **final_up_beginner → Query Tool**.
2. Используйте новую вкладку для таблиц, вопросов и проверок. Старую вкладку, открытую для postgres, можно закрыть: создание новой базы не переключает подключение старой вкладки.
3. Чтобы проверить подключение, в новой вкладке выполните отдельно:

```sql
SELECT current_database();
```

4. Во вкладке **Data Output** появится таблица ответа. В ней должно быть **final_up_beginner**. Если написано postgres — вы остались в старой вкладке, откройте Query Tool у нужной базы.

### 4. Выполните 01_schema.sql — создайте таблицы

1. В Query Tool базы **final_up_beginner** откройте **Open File → 01_schema.sql**.
2. Выделите мышью первую полную команду: от CREATE TABLE ... users до её закрывающего ); включительно.
3. Нажмите **Execute script**. Когда выделен фрагмент, выполняется выделенный SQL. Не выделяйте только одну строку вроде login TEXT PRIMARY KEY — сама по себе она не создаёт таблицу.
4. Посмотрите Messages: не должно быть ERROR.
5. Так же выделите и выполните полную команду создания questions.
6. Так же выделите и выполните полную команду создания results.
7. Слева раскройте **final_up_beginner → Schemas → public → Tables**. Нажмите правой кнопкой на Tables и выберите **Refresh**.
8. Должны появиться три таблицы: **users**, **questions**, **results**.

Если таблицы не появились, проверьте выбранную базу через current_database() и Messages. Не создавайте их наугад в другой базе.

### 5. Выполните 02_questions.sql — заполните тест

1. В той же вкладке, подключённой к **final_up_beginner**, откройте **Open File → 02_questions.sql**.
2. Выделите весь запрос от INSERT INTO до завершающей строки ON CONFLICT ... ;. Все пять вопросов — части ОДНОГО запроса.
3. Нажмите **Execute script**, проверьте Messages.
4. Слева нажмите правой кнопкой на **questions → View/Edit Data → All Rows**.
5. В открывшейся таблице должны быть **пять строк вопросов**. Это данные PostgreSQL, а не просто текст из файла.

users и results сейчас могут быть пустыми — это правильно. Пользователей добавит регистрация, а результаты — кнопка завершения теста в app.py.

### 6. Используйте 03_check.sql для проверки

Откройте этот файл в Query Tool базы **final_up_beginner**. Выделяйте и выполняйте каждый SELECT отдельно. Ответ читайте в **Data Output**:

1. SELECT current_database() — имя базы должно быть final_up_beginner.
2. SELECT login, role ... FROM users — список зарегистрированных аккаунтов. До регистрации он пустой.
3. SELECT id, question, correct ... FROM questions — пять вопросов и правильные номера.
4. SELECT student_login, score, grade ... FROM results — сохранённые оценки. До прохождения он пустой.

Не ждите одинакового содержимого от всех запросов: каждый проверяет свою часть базы. Messages показывает успешное выполнение или ошибку, Data Output — строки ответа SELECT.

### 7. Подключите эту базу к приложению

1. В settings.py поле dbname должно быть **final_up_beginner** — то же имя, которое проверили в pgAdmin.
2. user, password, host и port должны соответствовать тому серверу, к которому подключились в pgAdmin. Если у вашего сервера другой порт или пользователь, укажите свои значения.
3. После полной сборки app.py запустите его из папки testing_app.
4. Зарегистрируйте ученика через окно программы. Вернитесь в pgAdmin и заново выполните SELECT пользователей из 03_check.sql: должна появиться его строка.
5. Войдите учеником и завершите тест со всеми пятью выбранными ответами. Заново выполните SELECT результатов: должна появиться строка с логином, количеством верных и оценкой.
6. Пройдите тест второй раз: появится ещё одна строка результатов. Старую строку новое прохождение не заменяет.

**После действий в приложении старый ответ SELECT в pgAdmin сам не меняется:** выполните SELECT снова. Закройте и откройте приложение — сохранённые пользователи и оценки должны остаться.

Если изменили только текст .sql-файла, база от этого не изменилась. В этой работе CREATE TABLE IF NOT EXISTS не переделывает уже существующую таблицу, а повтор заполнения с ON CONFLICT пропускает существующие вопросы. Для задания достаточно первоначального создания и заполнения; редактирование структуры и вопросов не требуется.

При обычной настройке Query Tool изменения сохраняются автоматически. Если вы сами выключили Auto commit, после успешных INSERT потребуется Commit; для начальной сборки используйте включённый Auto commit. CREATE DATABASE выполняйте отдельно, не внутри BEGIN/COMMIT.
